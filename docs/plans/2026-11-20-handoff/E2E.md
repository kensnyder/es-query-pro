# E2E handoff — cross-module scenarios

No library bug found: every scenario passes on both targets as written; nothing is marked `test.failing`/`test.todo`. All files import the library from `../../index` (public surface); `MigrationParams` is used now that DOCS exports it.

## Files (all new)
- `src/e2e/helpers.ts` — test-only helpers (`HOLD`, `release`, `releaseTasks`, `track`, `copiedAtLeast`, `aliasTargets`, `allDocs` with duplicate detection, `idsOf`). Type-only `@elastic` import (passes `typesOnlyImports.spec.ts`).
- `src/e2e/lifecycle.integration.test.ts` (11 tests, scenario 1) — `SchemaRegistry({ books, places })` → `migrateIfNeeded` (both `created`, `getStatus` all `current`) → `putBulk` → match + `filter` (filter leaves `_score` unchanged), range filter + sort + `limit`/`page` (pages 1–3, `_sort`), `aggregateTerm` alone and under a filter (bucket keys/counts), `findFirst`/`count`/`findFirstOrThrow` (`NotFoundError` 404) → **redeploy** with books v2 through the registry (`migrated` / `unchanged`, v1 gone, old manager reads via alias) → `updateMany` (top-level, nested-object path, v2-only field; unknown key refused with `request: null`) → `count` → `deleteMany` (term, then no callback = all, D6) → `dropAll` (`DROPPED`, aliases gone, reads become `errorKind: 'response'` envelopes, second run `MISSING`).
- `src/e2e/versionBump.integration.test.ts` (1 test, scenario 2) — 40 seeded docs; v1 → v2 (v2 adds `tag`) held with `HOLD`; a sequential writer alternating v1/v2 managers runs `put` (new id), `patch` (each seeded doc once), `findById`, `count` before release (asserted on v1), through the copy, swap and cleanup, and 5 iterations after. Asserts: zero op errors, `MIGRATED`, no duplicates, `total` = seeded + puts, every doc equals its last write (`Bun.deepEquals`), dynamic-then-mapped `tag` searchable on v2, re-run `CURRENT`. Each doc is written at most once after seeding, so the documented post-swap window (two old writes beat one new write) cannot decide the result; stale reads are counted and allowed only in the `running` phase (0 observed in 7 runs).
- `src/e2e/rollingDeploy.integration.test.ts` (2 tests, scenario 3) — four instances (2×v1, 2×v2): v1 `CREATED`/`CURRENT` → v2a `MIGRATION_STARTED` (held) → v1 restart `CURRENT` without touching v2 or alias → writes from both generations → v2b `MIGRATION_RESUMED` (`attached`, same task) → v1 again `CURRENT` (copy still running) → release, both `MIGRATED` → v1 `NEWER_VERSION_PRESENT` (v1 not recreated) but still writes/reads via alias → both v2 `CURRENT`; final: alias on v2 only, all 11 docs once. Second test: two v2 instances call `migrateIfNeeded()` in the same tick → one `MIGRATION_STARTED`, one `MIGRATION_RESUMED`, both `MIGRATED`, 12 docs, no duplicates.
- `src/e2e/hybridSearch.integration.test.ts` (9 tests, scenario 4) — places with `hnsw` (not `int8_hnsw`; see QB8). Ungated: lone knn + `filter`/plain conditions as filters, `findFirst`; `count`/`updateMany`/`deleteMany` with knn refuse without sending (server unchanged); knn + `sort` → `TypeError` envelope. `caps.retrievers`: two weighted knn in `linear` (order by weight), `page(2)` past the default window, `linear` + filter, knn + `rescore` (rescorer retriever). `caps.retrievers && caps.inference`: `semantic`, `rrf`, `rrf` + filter, `weightedSemantic` (contains clause wins), then a v1 → v2 migration of the `semantic_text` index and the same searches on v2.

## Surprises (not bugs)
- **`batchSize` applies to every migration pass**, not just the first copy (`requestsPerSecond` does, per its JSDoc). With `HOLD` (`batchSize: 1`) the catch-up passes copy ~4 docs/s on serverless; with 200 seeded docs and a writer the migration took 182 s (passes scanned 200 + 296 + 401 docs). Scenario 2 now seeds 40. DOCS: say in `batchSize`'s JSDoc/README that it also sizes the catch-up passes; a small value used to throttle slows the whole migration.
- Pass reports add up as expected under load: e.g. catch-up `total: 296` = `created: 96` (new puts) + `updated: 96` (patched docs, higher external version) + `versionConflicts: 104` (unchanged docs skipped).
- Not covered (timing-dependent, documented in IM5): the post-swap lost-update case and D2 deletes; scenario 2 avoids both by design.
