# F2 handoff — IndexNameManager

## Findings fixed (all reproduced by failing unit tests first)
- **B-024** `parseByName(fullName, separator = '~')`: throws `RangeError` unless 3 or 4 parts, the last is `v<version>` and every part is valid; a prefix containing the separator now throws instead of being dropped. Versions matching `/^(0|[1-9][0-9]*)$/` (safe integers) come back as numbers; others (`2024a`, `05`, `1.5`) stay strings so names round-trip.
- **B-025** The constructor validates every part and throws `RangeError`: separator non-empty and ES-legal; language non-empty; prefix/language/`v<version>` must not contain the separator; numeric version a non-negative safe integer, string version non-empty; `getFullName()` and `getAliasName()` must be valid ES names (lowercase; none of `\ / * ? " < > | , # :`; no whitespace/control chars; not starting with `- _ + .`; at most 255 UTF-8 bytes). Messages name the offending full name.
- **B-067** `name` regex is now `/^[a-z0-9][a-z0-9_-]*$/` (single chars, leading digit, `-` allowed). `isValidColumnName` and the `ColumnName` type were deleted (never called).
- **B-075** The 3 unused `@ts-expect-error` lines removed. tsc errors in `src/IndexNameManager/*`: 4 → 0.
- **S-011 (naming)** Specs for no-prefix construction, `parseByName` without a separator, prefix/separator validation (`IndexNameManager.rules.spec.ts`).

## Public API (all on the default export of `src/IndexNameManager/IndexNameManager.ts`)
- `static parseByName(fullName: string, separator = '~'): IndexNameManager` — throws `RangeError`.
- `static tryParseByName(fullName: string, separator = '~'): IndexNameManager | null` — new; null instead of throwing.
- `static compare(base: IndexNameManager, other: IndexNameManager): IndexNameRelation` — new; classifies `other` relative to `base`. Returns `'unrelated'` if separator, prefix, language or name differ; `'same'` if `String(version)` is equal (so `3` equals `'3'`); `'incomparable'` if versions differ and either is not `/^(0|[1-9][0-9]*)$/` (`2024a`, `03`); else `'older'` / `'newer'` by numeric order (digit strings, so beyond 2^53 too; `v10` is newer than `v9`).
- `export type IndexNameRelation = 'same' | 'older' | 'newer' | 'unrelated' | 'incomparable'` — new.
- `static isValidEsIndexName(name: string): boolean` — new; the ES-rule check above.
- Removed: `isValidColumnName()`, type `ColumnName`. Constructor errors are now `RangeError` (still `instanceof Error`).
