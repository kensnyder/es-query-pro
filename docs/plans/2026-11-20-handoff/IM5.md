## Design (`src/IndexManager/migrate.ts`; `IndexManager.migrateIfNeeded()` delegates)
`getStatus()` → `createOnly()` new (not in alias) → `_reindex` older→new, `dest.version_type: 'external'`, `conflicts: 'proceed'`, `wait_for_completion: false`, `refresh: true` → poll `GET _tasks/<id>` → catch-up pass → one `_aliases`: `remove {old, must_exist}` ×N + `add {new, is_write_index: true}` → `_refresh` old (reindex sees only refreshed docs; after the swap nothing writes to old) → final catch-up pass → verify: `sum(count(old))` must equal the final pass's `total` and the pass must account for every doc (copied or version-skipped) → delete old → delete `.tasks/_doc/<id>` (errors ignored) → restore mapping `_meta`. Unrelated indexes on the alias are never copied or removed. The first-copy task id is stored in the new index's mapping `_meta["es-query-pro-migration"]`, so a later run can attach to it on serverless (no tasks list there); on stateful, `GET _tasks?actions=*reindex&detailed` is the fallback. A concurrent run that swapped or cleaned up first is detected (alias already on new, or old indexes gone) and counts as success.

## Public API (breaking). Types are exported from `migrate.ts` and re-exported from `IndexManager.ts`
- `migrateIfNeeded(params?: MigrationParams): Promise<MigrationResult>`. Params: `onProgress`, `onComplete` (success only, once), `onError` (once), `slices` (`number | 'auto'`, default 1), `pollInterval` (default 1000, min 10), `timeout` (ms, default none), `maxPollErrors` (default 5, consecutive), `requestsPerSecond` (first copy only), `batchSize` (`source.size`). A callback that throws is ignored.
- `MigrationResult`: `{ success, code: MigrationCode, status, newName, aliasName, oldNames, recordsToMigrate, createdIndex, createdAlias, resumed, attached, taskId, request (reindex request or null), completion: Promise<MigrationOutcome>, took, error, errorKind, response }`.
- `MigrationCode`: `CREATED`, `ALIAS_CREATED`, `CURRENT`, `MIGRATION_STARTED`, `MIGRATION_RESUMED` (success); `NEWER_VERSION_PRESENT`, `INCOMPARABLE_VERSION`, `ALIAS_CONFLICT` (`success: false`, `error: null`); `STATUS_ERROR`, `COUNT_ERROR`, `CREATE_ERROR`, `ALIAS_ERROR`, `REINDEX_ERROR` (with error).
- `MigrationOutcome` (`completion` never rejects; it is already settled for non-migration codes and then carries the same code): `{ success, code: MigrationOutcomeCode, phase, oldIndexes, newIndex, alias, swapped, removedIndexes, passes: MigrationPassReport[], taskIds, cancelled, counts: {old: Record<string,number>, new} | null, failures, cleanupErrors, took, error, errorKind }`. Codes: `MIGRATED`, `REINDEX_FAILED`, `REINDEX_ERROR`, `POLL_ERROR`, `TIMEOUT` (`errorKind: 'timeout'`, name `MigrationTimeoutError`), `SWAP_ERROR`, `VERIFY_FAILED`, plus the immediate codes.
- `MigrationProgressDetails` gains required `phase: MigrationPhase` and `failures`; `percent` is 0–99 while running, and 100 only in the final `phase: 'done'` events (one per old index). `onComplete` gets `oldIndex` = old names joined with `,`.
- Also exported: `MigrationPhase`, `MigrationPassPhase`, `MigrationPassReport`, `MigrationRequest`, `IndexMigrateResult`; from `migrate.ts` only: `MIGRATION_META_KEY`, `findReindexInto`, `migrateIndex`, `MigratingIndex`.
- Removed result keys: none. The old `createdIndex: true` on a failed create is gone. No flush after migrating.

## D2 limitation (observed on serverless)
A doc deleted through the alias during the copy is back afterwards, both one already copied ('0') and one not yet copied ('5'). The first pass reads a snapshot taken when it starts, and there are no tombstones. Also: writes that reach the old index between the swap and the final pass are briefly invisible until that pass copies them. If two writes go to the old index and one to the new index in that window, the old index's value wins.

## Gate follow-up (after the coordinator's report)
- **D2 test failure on loaded serverless was a test-timing problem, not a library bug.** `findById` through the alias is a single-doc GET, and the alias swap is atomic. A read that finds the just-deleted '0' therefore had to hit v2, which means the 3-second copy (rps 2) had already finished and the swap happened between the delete and the read. Catch-up passes only copy old→new with external versions; nothing writes back into v1. Fix: mid-flight tests now hold the copy with `HOLD = { requestsPerSecond: 0.2, batchSize: 1 }` (25–45 s if left alone), wait on progress with `kit.waitFor`, assert `stillOn(alias, v1)` after the mid-flight reads (the swap is atomic and one-way, so this proves the reads hit v1), then `release()` the copy with a rethrottle. The D2 assertion itself is unchanged.
- **Real bug found on Docker, fixed:** a pass missed writes made to the old index within the last refresh interval, because reindex reads through search. The verify step caught it: v2 had 44 docs vs 45 in v1, so v1 was kept. The old index is now refreshed right before the final pass; a failed refresh fails that pass (`REINDEX_ERROR`, swapped, old kept).
- **Speed (round 2; `should migrate data` timed out at its own 20 s timer on serverless).** Measured on serverless for 3 books: 30.5 s. Each explicit `_refresh` there takes ~5 045 ms, and there were 4 (before each pass, and in verify); each pass also waited a full `pollInterval` before its first check. Now: one refresh (before the final pass); verify compares the unrefreshed old count with the final pass, with no refresh; polls start at 100 ms and double up to `pollInterval`. Measured: **14.2 s** (create 1.2 s, first pass ~6 s of which ~5 s is the task's own `refresh: true` on the new index, which must stay so reads after the swap see every doc, final refresh 5 s). Docker: under 1 s. `VERIFY_FAILED` now means the final pass did not read or account for every old doc; `counts.new` is informational.
- **Real bug, fixed:** a resume could attach to a task that was just cancelled (`completed: false`, `cancelled: true`). The recorded task is now ignored when cancelled. Unit test added.
