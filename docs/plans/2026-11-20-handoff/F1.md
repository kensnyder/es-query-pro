# F1 handoff — shared types (`src/types.ts`)

## Findings fixed
- **B-079** — `IndexExistParams` is now `Prettify<estypes.IndicesExistsRequest>`
  (was the alias-exists request). `IndexManager.exists()` accepts
  `flat_settings`, `include_defaults`, `local`, `ignore_unavailable`,
  `allow_no_indices`, `expand_wildcards`; `exists({ name })` no longer
  type-checks. `AliasExistParams` is unchanged (alias-exists request).
- **S-048 (type only)** — `RangeShape` widened to
  `string | number | Date | [RangeBound<string | Date>, RangeBound<string | Date>] | [RangeBound<number>, RangeBound<number>]`.
  Strict superset of the old type: `Date` alone, `Date` bounds, and `Date`
  mixed with string/date-math bounds (`[date, 'now']`). Numbers still cannot be
  mixed with strings or dates. `RangeBound<T>` unchanged. No change was needed
  in `QueryBuilder.ts`: `range()` already passes values through, and a `Date`
  serializes to ISO 8601.

## Declared in `src/types.ts` (complete list of changes)
- Changed: `IndexExistParams`, `RangeShape` (plus JSDoc on `RangeShape`).
- **No new names added.** `src/publicExports.spec.ts` pins every name exported
  through `index.ts` (`export * from './src/types'`), so a new type here would
  turn that spec red until DOCS. Hence the range options type is NOT here.
