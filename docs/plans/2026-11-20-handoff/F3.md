# F3 handoff — analyzer and utilities

## Findings fixed
- **B-072** (reproduce-first) — **reproduced** on serverless before the fix: `résumés` → `resume` but `resumes` → `resum`; `John's` → `john'`; a `match` for `resume cafe` missed a doc containing `Résumés of the café's staff`. Fixed: filter chain is now `english_possessive_stemmer, lowercase, asciifolding, english_stop, english_stemmer` (new `english_possessive_stemmer` filter, `stemmer`/`possessive_english`). It now matches the built-in `english` analyzer on unaccented text (tested), and accented stop words (`thé`) are removed.
- **B-073** — `normalizeTimeZone` / `offsetMinutesToString` throw `RangeError` for non-integer, non-finite and beyond ±1080 minutes; offsets with `mm >= 60` or beyond ±18:00; unknown, wrong-case or ES-rejected zone names. A non-string, non-number input throws `TypeError`. Integration test shows that ES returns 400 for every value the old code passed through (`+05:30.5`, `+NaN:NaN`, `+1666:40`, `+99:99`, `Foo/Bar`, `EST`, `america/new_york`).
- **S-034 (behavior)** — now also accepts `±HHMM`, `±HH`, `±H` (normalized to `±HH:MM`; `-00:00` → `+00:00`) and single-segment names (`GMT`, `CET`, `EST5EDT`, `US/Eastern`, ...). JSDoc states "minutes **east** of UTC, opposite of `Date#getTimezoneOffset()`" and recommends zone names over fixed offsets (DST).
- **B-074** — `isEmptyObject(value: unknown)` is true only for plain objects (prototype `Object.prototype` or `null`) with no `Reflect.ownKeys`. Arrays, Dates, Maps, Sets, class instances, symbol/non-enumerable keys → false.
- **S-035** — `isDefined<T>(value: T): value is NonNullable<T>`; works with `.filter(isDefined)`. No new tsc errors in `QueryBuilder.ts` from the narrowing.
- **S-011 (utility part)** — new specs `englishplus.spec.ts`, `isDefined.spec.ts` (with `expectTypeOf`); `isEmptyObject.spec.ts` covers arrays, Dates, Maps, Sets, symbols. Its baseline TS7009 is gone (`new f()` replaced by a class).

## How zone names are validated (observed on serverless ES, Bun 1.4.5 ICU)
- ES accepts all 445 `Intl.supportedValuesOf('timeZone')` names. ES rejects `EST`, `MST`, `HST`, `ROC` and wrong-case names (`utc`, `America/new_york`), all of which `Intl` accepts; Java short IDs (`PST`, `IST`, ...) are rejected by both.
- ES accepts `EST5EDT`, `CST6CDT`, `MST7MDT`, `PST8PDT`; Bun's `Intl` rejects them.
- Rule: case-sensitive shape check (each segment starts upper-case) → deny `EST/MST/HST/ROC` → allow the 4 POSIX-style names → otherwise `Intl.DateTimeFormat` must accept the name and must not only differ from it in case. Accepted names depend on the runtime's ICU data (Node may differ).
- Not supported (ES accepts them, the function rejects them): prefixed offsets `GMT+5`/`UTC+05:30`/`UT+5`, seconds `+02:00:00`, `SystemV/*`. `GMT+5` means UTC+5 to Java but `Etc/GMT+5` means UTC−5, so rejecting it avoids confusion.

## Breaking changes (CHANGELOG, for DOCS)
- `englishplus` produces different tokens: existing indexes that use it must be reindexed (`migrateIfNeeded` with a version bump).
- `normalizeTimeZone`, and therefore `QueryBuilder.dateHistogram()`, throws `RangeError` (was `Error`) and rejects `EST`, wrong-case names and out-of-range values that were previously passed through. It now accepts `+0530`, `+05`, `GMT`, `CET`, `EST5EDT`.
- `isEmptyObject` (public export) returns false for arrays, Dates, Maps, Sets, class instances and objects with symbol/non-enumerable keys.

## For other tasks
- **QB5** (histogram methods): no change needed; `dateHistogram()` keeps calling `normalizeTimeZone`. Its JSDoc/README for `timezone` can point at the accepted forms above. A `RangeError` from it is consistent with the "QueryBuilder throws RangeError" convention.
- **DOCS**: no export changes. README could document the `timezone` forms, the east-of-UTC sign, and the `englishplus` filter chain.
